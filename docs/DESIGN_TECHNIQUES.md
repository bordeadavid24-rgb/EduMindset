# How this page gets its personality

These are the techniques used in V2 and the job each one does here. This is an explanation of the implementation, not a final performance or accessibility test report.

| Technique | What it means here | Purpose and practical example |
| --- | --- | --- |
| Alpha cutout | A transparent background lets the photographed subject retain its own outline. The hero keeps Alex, his microscope, and a work-surface base. | The page can place colour behind the person without trapping him inside a rectangular photo card. |
| Photographic compositing and layering | The cutout sits in front of a large question mark on the yellow hero field. The layers are ordinary page elements. | Alex's real activity becomes part of the same scene as the message about learning through questions. |
| Art-directed crops | The portrait and auditorium photo use intentional `object-fit` and `object-position` settings, with different mobile crops. The hero also changes scale on mobile. | Preserve the face, apparatus, and useful human context when the available shape changes. This is more deliberate than shrinking the desktop layout. |
| Palette roles | Blue carries identity and action, pale yellow marks learning, and orange supplies a small warm emphasis. | A blue button means action; the yellow exercise surface means something to try. Orange is used for a question mark and underline rather than low-contrast body text. |
| Typographic hierarchy | One family, Bricolage Grotesque, supplies headlines, body text, and controls. Size, weight, spacing, and automatic optical sizing separate those jobs. | A visitor sees the main question first, then the short explanation, then the workshop action. Romanian diacritics remain part of the typography. |
| Information architecture | Content is ordered around what a visitor needs to understand and do. V2 brings the exercise and workshop programme before the longer project story. | Visitors can experience the idea and find the upcoming workshops before choosing to read mission, values, and background. The original copy remains available. |
| Microlearning | A small, self-contained activity teaches one idea inside the page. | The three-word exercise is optional and short, without a registration gate. It gives a sample of participation. |
| Active recall, or reamintire activă | Try to retrieve information from memory before looking at it again. Here the visitor reads three words, hides them, recalls them, and reveals them to compare. | The interface demonstrates the method instead of merely naming it. It makes no claim about an individual score, diagnosis, or guaranteed learning gain. |
| Progressive disclosure | Native expandable sections reveal detail when requested. | Workshop headings stay easy to scan; their complete bullets are available on opening. Longer personal and project explanations use the same principle. |
| Mobile reflow and touch design | Main two-column regions become a vertical reading sequence, controls retain usable touch areas, and input text stays 16px. | The image, headline, and CTA receive their own phone arrangement. Hover effects are reserved for devices that support hover, avoiding sticky touch feedback. |
| Safe-area spacing | CSS reads the device's safe-area insets, with `viewport-fit=cover` enabled. | Header and footer spacing can accommodate screen cutouts and home-indicator regions. This still needs real-device inspection. |
| Responsive pictures | `picture` chooses a suitable format or media branch. `srcset` supplies image widths; `sizes` tells the browser their expected displayed width. | A narrow phone need not download the largest transparent hero. The same subject is supplied at multiple resolutions. |
| AVIF and WebP tradeoff | The hero prefers AVIF on desktop and WebP on mobile, with WebP as a fallback. Both preserve transparency. | AVIF can reduce transferred bytes, while its decode cost can matter on slower devices. WebP is the current mobile choice to balance those costs. Results depend on device and image, so this is a measured-design choice rather than a universal rule. |
| Preload and lazy loading | Media-specific hero preloads make the first important image discoverable early. Lower portraits, auditorium imagery, and QR use lazy loading. | Spend early bandwidth on the first scene instead of every image on the page. Font assets are also explicitly preloaded in the current HTML. |
| Layout reservation and CLS | Explicit image dimensions, image aspect ratios, and a minimum exercise-stage height reserve space before content finishes loading or changes. | Reduce unexpected movement while a photo loads or exercise words are replaced. CLS means cumulative layout shift, a measure of visible layout movement. This document does not claim a final CLS score. |
| Local variable fonts | Font files are served with the site rather than fetched from a third-party font stylesheet. Variable fonts cover a range of weights in one face. | The single family keeps headline and body styling related, covers Romanian glyphs, and avoids a second family download. Font preloads should match the files actually used by CSS. No metric improvement is claimed here without an audit. |
| Progressive enhancement | The content is useful as HTML first; JavaScript adds the recall controls, theme switch, menu convenience, and email preparation. | Native workshop disclosures and links survive script failure. A no-script instruction lets visitors try the recall idea manually. |
| Keyboard and reduced-motion support | Buttons, links, forms, and summaries retain native keyboard behavior and visible focus. Reduced-motion preference removes displacement and smooth scrolling. | Someone can open a workshop or close the menu with Escape without relying on a mouse or decorative animation. |
| Honest email handoff | The form prepares an addressed message for the visitor's email app. It cannot confirm sending or delivery. | The page says what happens, offers a copy option, and handles messages too long for a reliable mailto link without pretending they were sent. |

The hero image is an **AI-assisted, source-derived cutout**, not an untouched original photograph. The edited PNG and exact prompt are stored in `assets/derived/alex-laborator-cutout-v2.png` and `assets/derived/alex-laborator-cutout-v2.prompt.txt`. Responsive derivatives are built by `scripts/prepare-v2-assets.mjs`. The portrait and auditorium images come from the user's supplied photographs. Neither proves a previous EDU MindSet or UnitED event.
